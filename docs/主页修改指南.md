网站仅保留英文版，国内奖项使用中文原名。日常修改 Markdown 或 YAML，再用 GitHub Desktop 提交和推送即可，不必安装本地 Jekyll 环境。

## 2. 新增论文

在 `_data/publications.yml` 的最上面复制一条已有记录，再填写实际信息。文件中的顺序就是网页上的顺序。

```yaml
- title: "Your Published Paper Title"
  authors: ["J. Zhai", "H. Dui", "Another Author"]
  venue: "Journal Name"
  year: 2027
  volume: "100"
  issue: "2"
  doi: "10.xxxx/your-real-doi"
  pdf: "/files/your-paper.pdf"
  code: "https://github.com/jiabaoz-linus/your-repository"
```

以上仅是格式示例，不要原样发布。每条记录以 `- title:` 开始，其余字段缩进两个空格，不要使用 Tab。

- `authors` 按正式署名顺序填写，你的署名统一写 `J. Zhai`，网页会自动加粗。
- `doi` 只填写 DOI 编号，不带 `https://doi.org/`。
- `volume`、`issue`、`doi`、`pdf`、`code` 都可省略。
- 论文卡片不显示简介，已有的 `summary_en` 或 `summary` 字段不会显示，也无需新增。
- PDF 文件放入 `files` 文件夹，再填写 `/files/文件名.pdf`；文件名大小写必须一致。

保留正文中的 `{% include publications.html %}`。新增论文只需改数据文件，不必编辑卡片模板。卡片排版在 `_includes/publications.html` 和 `assets/css/main.scss` 中维护。

### 新增会议记录

导航栏的 Conferences 对应 `_data/conferences.yml`。采用与期刊论文相同的卡片排版：题目、作者、会议名称和年份，会议奖项单独加粗突出。新增时在最上方复制已有记录并修改，例如：

```yaml
- name: "SPIES"
  full_name: "Full Conference Name"
  year: 2027
  url: "https://example.org/"
  award: "Best Presentation"
  paper_title: "Your Presented Paper Title"
  authors:
    - name: "Jiabao Zhai"
      highlight: true
    - name: "Coauthor Name"
      corresponding: true
```

以上仅为格式示例，请替换成真实信息。`name` 填写会议简称，`full_name` 填写全称，`year` 填写年份。`award` 没有就删除；`highlight: true` 加粗作者姓名，`corresponding: true` 标注通讯作者星号。`full_name` 和 `url` 可省略。

如需提供论文 PDF，把文件放进 `files`，再添加 `pdf: "/files/your-conference-paper.pdf"`。会议记录与 Publications 分开维护。保留正文中的 `{% include conferences.html %}`，不必逐次修改页面模板。

## 3. 教育背景、短期交流与校徽

修改 `_data/education.yml`：第一组 `entries` 是学历，第二组是短期交流。每条记录按时间、学位或身份、学校与导师、校徽四列显示，窄屏自动换行。

```yaml
- entries:
  - dates: "2023.09 ~ 2026.06"
    qualification: "Master's degree in Management Science and Engineering"
    school: "Zhengzhou University"
    school_url: "https://www.zzu.edu.cn/"
    logo: "/images/ZZU_Logo.png"
    advisor: "Prof. Hongyan Dui"
    advisor_url: "https://www7.zzu.edu.cn/glxy/info/1142/4169.htm"
```

这是局部格式示例，新增记录时复制已有记录即可，不要用它覆盖整个文件。

日期统一使用 `YYYY.MM ~ YYYY.MM`，月份写两位数字；在读经历写 `2026.08 ~ Present`。不要填写没有依据的月份。交流记录可填写 `department` 和 `topic`，不需要的信息直接省略。CUHK 交流目前不显示具体导师姓名。

保留正文中的 `{% include education.html %}`。学校图片放在 `images` 文件夹，用记录中的 `logo` 指定：

| 学校 | 图片 |
| --- | --- |
| HKUST (Guangzhou) | `/images/HKUST(GZ)_Logo.png` |
| Zhengzhou University | `/images/ZZU_Logo.png` |
| The Chinese University of Hong Kong | `/images/CUHK_Logo.png` |
| National University of Defense Technology | `/images/NUDT_Logo.png` |

更换校徽时，替换原图或修改 `logo` 路径即可。上传时记得把新增图片一起提交。图片尺寸在 `assets/css/main.scss` 的 `.education-logo-link img.education-logo` 中控制，并保持原始比例。

## 4. 更新 CV

导航栏的 **CV ↗** 直接在新标签页打开 `files/Jiabao_CV.pdf`。当前文件来自你提供的 `Jiabao_CV_中文.pdf`。

以后更新简历时，把新版 PDF 覆盖到 `files/Jiabao_CV.pdf`，保持文件名不变，再 Commit 和 Push。可以换成英文 PDF，无需更改导航。

如果需要改文件名，同时修改 `_data/navigation.yml` 中 CV 的 `url`。`new_tab: true` 表示在新标签页打开。请勿填写电脑上的 `C:\...` 路径，网站中的路径应为 `/files/文件名.pdf`。

## 5. 修改正文、奖项与导航

打开 `_pages/about-en.md` 修改正文对应段落。专利名称使用简历中的中文原名，保留申请号。荣誉奖项单独在 `_data/honors.yml` 中维护，国内奖项使用中文官方名称，周围的导航和章节标题保持英文。例如：

```yaml
- year: "2025"
  title: "硕士研究生国家奖学金"
- year: "2023 ~ 2025"
  title: "河南省教育厅研究生学业奖学金"
```

奖项原文只有年份时保留年份，不补月份；年份区间使用 `~`。奖项按数据文件中的顺序显示。模板自动标明中文语言，并用统一的年份列对齐；手机端年份置于奖项名称上方。

保留正文中的 `{% include honors.html %}`。请不要把奖项改成用 `|` 分隔的 Markdown 列表，Jekyll 可能将每条记录解析为独立表格，导致列宽不同。

保留 `<span class="anchor" id="honors"></span>` 等章节定位点。新增章节时在 `_data/navigation.yml` 的 `en` 中添加对应 `#id`；PDF 链接使用 `/files/...`。页面导航高亮只处理章节链接，CV 不参与章节高亮。

桌面端左侧导航固定显示，手机端点击顶部菜单按钮展开侧栏。点击章节、遮罩或按 Esc 关闭菜单。相关样式在 `assets/css/main.scss`，菜单行为在 `assets/js/site-navigation.js`。

## 6. 修改个人信息和头像

浏览器标签页标题单独由 `_config.yml` 中的 `browser_title` 控制，直接修改这一行即可：

```yaml
browser_title: "Jiabao ZHAI (翟嘉宝) | Academic Homepage"
```

引号内是完整标题，不会再自动拼接后缀。这个变量只影响浏览器标签页标题。修改后提交并推送；使用本地 Jekyll 时需要重启服务。

修改 `_config.yml` 中的 `author`：

```yaml
author:
  name: "Jiabao ZHAI"
  avatar: "/images/西施惠.jpg"
  bio: "Ph.D. Student · HKUST (Guangzhou)"
  location: "Guangzhou, China"
  email: "jzhai585@connect.hkust-gz.edu.cn"
  github: "jiabaoz-linus"
```

这是局部示例，不要覆盖整个配置文件。Google Scholar、ResearchGate 等链接也在 `author` 下。侧栏研究方向摘要由 `description` 控制。换头像时放入新照片并更新 `avatar`；浏览器标签页使用默认图标，未设置自定义图标。

## 7. 当前网站地址与发布

GitHub 上的实际账号为 `jiabaoz-linus`，仓库为 `jiabaoz-linus.github.io`，对应地址为 **https://jiabaoz-linus.github.io/**。

```yaml
url: "https://jiabaoz-linus.github.io"
baseurl: ""
repository: "jiabaoz-linus/jiabaoz-linus.github.io"
```

本地文件夹仍叫 `jiabaoz.github.io` 不影响发布，无需为了匹配线上仓库名称而移动文件夹。

1. 在 GitHub Desktop 中选中本仓库，确认分支为 `master`。
2. 查看 `Changes`，确认正文、数据、PDF 和图片均包含在提交内。
3. 填写说明，点击 **Commit to master**，再点击 **Push origin**。
4. 在仓库 **Actions** 中等待 Pages 构建成功。
5. 到 **Settings → Pages → Visit site** 查看，必要时按 `Ctrl + F5` 刷新。

只保存文件或只 Commit 不会更新线上网站。首次配置 Pages 时，使用 **Deploy from a branch → master → /(root)**，网站源码不在 `docs` 文件夹中。

日常不需要安装 Jekyll；若已装 Ruby、Bundler 和 Jekyll，可在项目目录运行：

```powershell
bundle install
bundle exec jekyll serve --livereload
```

默认访问 `http://127.0.0.1:4000/`，以终端显示的地址为准。修改 `_config.yml` 后需要重启本地 Jekyll。

## 8. 访客统计

独立统计页面：https://flagcounter.me/details/kJh 。它按 IP 大致位置统计访客国家或地区和访问量，不公开完整 IP。国家旁的数字是独立访客数，同一个 IP 在该计数器中只记一次；`Pageviews` 是浏览量，重复加载也会累计。详见 [官方统计规则](https://flagcounter.me/faq)。

正式图片地址必须使用 `https://flagcounter.me/kJh`。`https://flagcounter.me/api/counters/kJh/image` 是不计数的预览接口，只显示现有数据，不能用于正式网站的访问统计。按 [官方嵌入说明](https://flagcounter.me/for-blogs) 使用公共图片地址即可，不需要额外的计数脚本或刷新参数。

本地预览也会加载正式图片，因此会计入浏览量。浏览器拦截统计图片或网络无法连接第三方服务时，该次访问可能不会计入。历史上使用预览接口而漏记的访问无法补回。

`_config.yml` 中 `visitor_counter.enabled: false` 可隐藏组件；`image_url` 控制图片，`stats_url` 控制点击后打开的页面。标题及说明在 `_data/i18n.yml` 的 `en` 中维护。

## 9. 常见问题

- **构建失败**：先检查 YAML 缩进、引号、冒号，查看 Actions 中的错误信息。
- **PDF、照片或样式无法加载**：检查文件名大小写及 `_config.yml` 的 `baseurl`；当前根站点应为空字符串。
- **CV 仍然是旧版**：确认新 PDF 已 Push，再强制刷新 PDF 页面或用无痕窗口打开。
- **推送后没更新**：确认已推到 `master`，并等待 Pages 构建完成。
- **Get Citation Data 失败**：这是原模板的引用抓取工作流，与 Pages 发布是不同任务，当前论文显示不依赖它。

日常流程：**修改 → 保存 → 检查 Changes → Commit → Push → 查看网页**。
