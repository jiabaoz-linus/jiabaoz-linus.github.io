# 翟嘉宝的主页修改指南

本项目使用 Jekyll：你修改 Markdown 正文和 YAML 数据，Jekyll 将它们生成网页。日常更新不需要改 HTML 或 CSS。

**不必在电脑上安装 Jekyll。** 最省事的日常流程是：用编辑器修改文件，用 GitHub Desktop 提交并上传，让 GitHub Pages 自动构建。只有需要本地实时预览时，才考虑第 7 节的安装方式。

### 中英文页面如何工作

默认访问网站根地址时显示英文；点击桌面侧栏顶部的 **中文** 按钮进入 `/zh/` 页面，点击 **English** 返回英文。手机端顶部的语言按钮也始终显示，无需先展开菜单。在论文等章节点击语言按钮，会跳转到另一种语言的相同章节。

桌面端左侧固定显示头像、个人信息和章节菜单，阅读时菜单会高亮当前章节。手机端点击顶部菜单按钮展开侧栏，点击章节、空白遮罩或按 Esc 关闭。以后新增导航项，在 `_data/navigation.yml` 的 `en` 和 `zh` 中各添加一项，并在两份正文中添加对应的章节 `id`。侧栏样式集中在 `assets/css/main.scss` 的 “Fixed profile and section navigation” 部分；手机菜单和高亮行为在 `assets/js/site-navigation.js` 中维护。

简介、奖项等正文独立维护，修改时请同步更新英文和中文文件；教育背景、交流和论文则共用数据文件。保留文件开头的 `permalink`、`lang`、`translation_url` 和 `translation_lang` 设置，以及正文中各节相同的 `id`，语言切换才能正确定位。网站根地址始终默认英文，不会根据浏览器语言或上次访问记录自动切换。

用 VS Code 打开整个 `jiabaoz.github.io` 文件夹，左侧找到对应文件。保存快捷键是 `Ctrl + S`。

主页不展示项目经历和在审论文。完整简历含这些内容，因此当前没有把完整 PDF 作为主页下载附件。

### 教育背景、交流与校徽

教育背景采用无边框的四列排版：时间、学位或身份、学校与导师、校徽。窄屏会自动换行，手机端校徽仍在每条记录右侧。修改 `_data/education.yml` 即可同时更新两种语言；不必编辑 HTML。

文件第一组 `entries` 是三段学历，第二组是短期交流。新增记录时复制完整的一项，修改 `dates`（时间）、`qualification`（专业与学位或交流身份）、`school`（学校）、`school_url`（学校链接）、`logo`（校徽路径）。各项中的 `en` 与 `zh` 分别填写英文与中文。学历可填写 `advisor` 和 `advisor_url`；交流可填写 `department`、`host`、`host_url` 和 `topic`。没有的信息直接省略。请保留两份正文中的 `{% include education.html %}`。

### 底部访客统计

已为本主页创建独立的 [flagcounter.me 计数器](https://flagcounter.me/details/kJh)，英文和中文页面共用统计。它显示访客国旗及访问量，按 IP 的大致位置识别国家或地区，不公开完整 IP。点击组件可打开详细统计。IP 归属地不等于访客的实际所在地，VPN、网络出口等可能影响结果。图片加载一次就增加一次浏览量，自己预览和刷新也会计入；服务不可用或访客屏蔽远程图片时不会准确累计。

开关和公开链接在 `_config.yml`：将 `visitor_counter.enabled` 改为 `false` 可隐藏组件；`image_url` 是统计图片链接，`stats_url` 是点击后打开的统计页面。中英文标题和说明在 `_data/i18n.yml`。

管理信息保存在本机 `C:\Users\Darli\AppData\Local\Codex\JiabaoHomepageTools\visitor-counter-access.txt`，不在仓库中。打开后搜索 `password` 可找到创建时的一次性密码。请自行保管，**不要把该文件或密码提交到 GitHub**。以后可用该密码在 flagcounter.me 中认领计数器或修改外观；丢失密码无法找回。更换服务时填写新计数器的两个公开链接即可，不能复制他人计数器链接，否则会共用其统计。

## 2. 新增一篇论文：最常用的操作

打开 `_data/publications.yml`，在最上面已有论文之前复制下面的记录，再把示例文字改成真实信息。网页按文件中的顺序显示，通常将最新论文放在最上方。

```yaml
- title: "Your Published Paper Title"
  authors: ["J. Zhai", "H. Dui", "Another Author"]
  venue: "Journal Name"
  year: 2027
  volume: "100"
  issue: "2"
  doi: "10.xxxx/your-real-doi"
  summary: "用一句中文介绍这篇论文解决的问题和主要方法。"
  summary_en: "Briefly describe the problem and main method in English."
```

这些是格式示例，不是实际论文，请勿原样发布。

| 字段 | 含义 | 如何填写 |
| --- | --- | --- |
| `title` | 论文标题 | 保留英文正式标题，用英文双引号包起来 |
| `authors` | 作者 | 按论文署名顺序填写；你的姓名统一写 `J. Zhai`，网页会自动加粗 |
| `venue` | 期刊或会议 | 使用正式名称 |
| `year` | 发表年份 | 直接写数字 |
| `volume` | 卷号 | 可选；暂无卷号时整行删除 |
| `issue` | 期号 | 可选；暂无期号时整行删除 |
| `doi` | DOI | 只写编号，不写前面的 `https://doi.org/`；暂无 DOI 时整行删除 |
| `summary` | 中文简介 | 可选；不需要时整行删除 |
| `summary_en` | 英文简介 | 可选；英文页仅显示这个字段，不会自动翻译中文简介 |
| `pdf` | 论文 PDF | 可选；见下一节 |
| `code` | 代码仓库链接 | 可选；填完整 `https://...` 地址 |

注意 YAML 缩进：每条论文第一行以 `- title:` 开始，后续字段前有 **两个空格**。不要用 Tab。冒号后保留一个空格，标题里有冒号也放在引号内。新增论文只改这个数据文件，中英文页面会同时增加这篇论文，不必在两份正文中重复添加。

论文采用单列卡片，每篇独占一行，标题、作者、期刊、简介和链接各有自己的位置。你的署名自动加粗。修改卡片排版时编辑 `_includes/publications.html` 和 `assets/css/main.scss`；日常增加论文不需要改这两个文件。

论文列表只添加已发表成果。在审论文不写入这个文件。

### 增加 PDF 和代码链接

1. 在仓库根目录新建 `files` 文件夹（已有则直接使用）。
2. 放入你可以公开分享的论文版本，建议使用简短的英文文件名，如 `chart-2025.pdf`。
3. 在对应论文记录中增加两行；只有 PDF 时仅增加 `pdf`：

```yaml
  pdf: "/files/chart-2025.pdf"
  code: "https://github.com/IceTaeyeon/your-repository"
```

本地路径以 `/files/` 开始即可，不要手动加仓库名。页面会自动补上网站前缀。请不要把 Windows 的 `C:\...` 路径写入网页。

## 3. 修改正文：简介、专利、奖项等

中文正文打开 `_pages/about.md`，英文正文打开 `_pages/about-en.md`，找到对应标题后直接修改文字。文件开头两行 `---` 之间是页面设置，正文从第二个 `---` 后开始。

常用 Markdown 写法：

```markdown
## 荣誉奖项

- **2027**｜你的新奖项
- **2026**｜另一项奖项

这是普通段落，**这样写是加粗**。
[李翔宇教授](https://xiangyu5262985.github.io/)
```

标题前的 `<span class="anchor" id="honors"></span>` 是导航定位点，保留它。`{% include publications.html %}` 会自动插入论文列表，也保留它。

简历中重复的“2023 - 2025 年河南省教育厅研究生学业奖学金”在主页只列一次；“参与整理导师学术专著”按参与整理描述，不写成你独立著作。

### 在教育背景后添加校徽

校徽文件放在仓库的 `images` 文件夹。在 `_data/education.yml` 中找到对应学校，设置该项的 `logo` 路径，例如：

```yaml
      school:
        en: "Zhengzhou University"
        zh: "郑州大学"
      logo: "/images/ZZU_Logo.png"
```

以后换学校 logo，只需修改该项的 `logo` 文件名；替代文字会自动使用当前页面语言对应的学校名。文件名的大小写、括号和扩展名必须与 `images` 中实际文件一致。模板会自动补上网站地址前缀，不必编辑两份正文。

| --- | --- |
| 香港科技大学（广州） | `images/HKUST(GZ)_Logo.png` |
| 郑州大学（硕士、本科共用） | `images/ZZU_Logo.png` |

图片的显示尺寸统一由 `assets/css/main.scss` 中的 `.education-logo-link img.education-logo` 控制：宽屏最大宽度 `155px`、最大高度 `68px`；中等屏幕最大宽度 `130px`；手机最大宽度 `108px`、最大高度 `56px`。图片完整显示并保留比例，位于每条记录右侧。需要调整大小时修改样式即可，不必处理原图。

上传时除了教育数据和样式文件，记得把新校徽图片一起 Commit 和 Push，否则线上页面无法加载图片。

## 4. 修改邮箱、单位、照片和学术链接

打开 `_config.yml`，主要修改 `author:` 下的字段，例如：

```yaml
author:
  name: "翟嘉宝 Jiabao Zhai"
  name_en: "Jiabao ZHAI"
  avatar: "/images/jiabao-monogram.svg"
  bio: "香港科技大学（广州） · 博士生"
  bio_en: "Ph.D. Student · HKUST (Guangzhou)"
  location: "中国 · 广州"
  location_en: "Guangzhou, China"
  email: "jzhai585@connect.hkust-gz.edu.cn"
```

这是局部示例，不要用它覆盖整个配置文件。现有 `author:` 中还有学术链接等字段，按需修改即可。

不带 `_en` 的姓名、单位和地点用于中文页，带 `_en` 的用于英文页；`description` 和 `description_en` 分别控制侧栏中的中文和英文研究方向描述。头像、邮箱、学术平台链接由两种语言共用。

当前头像由 `avatar` 字段指定。换照片时，将照片保存为 `images/jiabao.jpg`，再把 `avatar` 改为 `"/images/jiabao.jpg"`。建议用正方形照片。浏览器标签页图标单独使用 `images/jiabao-monogram.svg`，不随照片自动改变。

修改 `_config.yml` 后，若本地预览已启动，需要先按 `Ctrl + C` 停止，再重新启动。

## 6. 修改后怎么发布：推荐 GitHub Desktop

1. 在 GitHub Desktop 中选择本地这个仓库，确认当前分支是 `master`。
2. 左侧 `Changes` 查看修改过的文件，点击文件核对内容。论文 PDF 如有新增，也要出现在这里。
3. 在左下角 `Summary` 写一句说明，例如 `Add a new published paper`。
4. 点击 **Commit to master**，再点击 **Push origin**。
5. 这是更新你自己的 `IceTaeyeon/jiabaoz.github.io`，无需向模板作者发 Pull Request。
6. 在 GitHub 仓库的 **Actions** 中等待 Pages 构建成功，再打开网站确认。若浏览器仍显示旧内容，可按 `Ctrl + F5`。

`Commit` 是保存到本地 Git 历史；`Push` 才是上传到 GitHub。只保存文件或只 Commit 不会更新线上网页。

### 首次启用 GitHub Pages

进入你自己的仓库 **Settings → Pages → Build and deployment**：

- Source：**Deploy from a branch**
- Branch：**master**
- Folder：**/(root)**
- 点击 **Save**，等待构建完成。

配置方式见 [GitHub 官方发布指南](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。不要选择 `/docs`，本项目的网站源码在仓库根目录。

## 7. 本地预览（可选）

日常也可以上传后查看 GitHub Pages；本地预览适合上传前检查。

本项目需要 Ruby、Bundler 和 Jekyll。安装环境可参考 [Jekyll Windows 安装说明](https://jekyllrb.com/docs/installation/windows/)。在安装了 Ruby + Devkit 的电脑上，在仓库目录终端运行：

```powershell
bundle install
bundle exec jekyll serve --livereload
```

默认访问 `http://127.0.0.1:4000/jiabaoz.github.io/`；以启动后终端显示的 `Server address` 为准。按 `Ctrl + C` 停止服务。仓库也保留了 `run_server.bat` 作为启动入口。

如果 `bundle install` 提示无法访问镜像，可运行 `bundle config unset --local mirror.https://rubygems.org` 后重试。

## 8. 常见问题

- **新增论文后构建失败**：检查 YAML 缩进、英文引号和冒号；先对照已有一条记录。
- **点击导航跳到错误页面**：检查 `_data/navigation.yml` 中的 `#publications` 等值与正文的 `id` 是否一致。
- **页面没有样式或照片不显示**：检查 `_config.yml` 的 `baseurl` 是否与仓库名称一致，文件名大小写是否一致。
- **修改后线上没更新**：确认已 Push 到 `master`，再看 Actions 中的 Pages 构建是否成功。
- **Get Citation Data 工作流失败**：这是原模板的 Google Scholar 抓取任务。当前主页直接链接你的 Google Scholar，不依赖自动引用统计；它与 Pages 发布任务不同，无需为了显示论文配置该抓取任务。
- **想撤销尚未提交的单个修改**：先备份需要保留的内容，再在 GitHub Desktop 中对该文件选择 Discard Changes。

每次更新的顺序：**改文件 → 保存 → 检查 Changes → Commit → Push → 查看网页**。
